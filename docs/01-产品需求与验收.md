# 产品需求与验收

2026-11-20 · 第一阶段提案

## 产品定义

给同时使用个人邮箱和工作邮箱的人一个统一收件台。在电脑上批量处理，在手机上读信、回复和看附件，离线时仍能查到已保存的材料。软件免费，全部客户端功能向所有用户开放。支持简体中文首启、中文搜索、系统字号、地区时间与时区，界面文案保留翻译入口。

**免登录**意味着没有本产品的注册、手机号绑定和会员账户。首次启动有「直接进入」「导入邮件」「添加已有邮箱」三条路径。前两条可以断网使用；第三条由用户向原服务商授权。本阶段提供邮件客户端，邮箱地址和投递由用户选用的服务商提供。

**本地化**意味着邮件缓存、索引、规则、联系人、待办、模型推理和诊断默认留在设备上。普通收发只访问已配置邮箱所需的协议和授权端点。未添加邮箱、未开启可选连接时，断网首启完整可用，联网首启也不自动请求产品服务器、追踪服务、外部图片或模型下载。用户可查看每种可选连接的目的地、数据和关闭方式。

## 三条主流程

1. **从电脑换到手机。** 在电脑上用两个邮箱收信，将一封邮件设为待办，保存经常使用的回复模板。手机无需注册，可重新授权两个邮箱；通过加密迁移包或双方主动配对，带过去模板和待办。列表上始终看得到每封信所属账号，回复前可核对发件身份。
2. **在飞机上接着工作。** 出发前把一个文件夹设为离线可用；飞行模式下按发件人或中文附件名找到信、打开已下载的附件，撰写回复。回到网络后，发件箱显示排队、正在提交或服务商已接受。回执不明的信保留原稿，应用重启也不会擅自重发。
3. **无需买会员处理高频事务。** 财务来信按规则聚合，输入快捷文本并套用相应签名，点附件返回所属邮件；同一组操作在四端免费。寄特别大的文件时，先显示邮箱的普通附件限制与可选分享目的地，由发件人决定走哪条路径。

## 第一阶段功能与验收

### 本次确定的默认行为

| 使用场景 | 产品行为与验收 |
| --- | --- |
| 从统一收件箱写信 | 有多个已配置的邮箱时，首次新建邮件须先指定默认发件邮箱，以后直接显示其完整地址。可改本封发件人，也可在设置中更改默认值；两次操作独立。若默认账号已失效，重新选择。单个邮箱内写信用当前账号，回复用原信所属账号，继续编辑草稿用草稿已保存的身份。没有邮箱时仍可写本地草稿。 |
| 发送前检查 | 正文提到随附文件而附件为空时，可补附件或明确按原文发送。用户为一个联系人指定常用发件邮箱后，用其他账号写给此人会提示，可切回或保留本封选择。没有指定关系时不根据邮箱域名猜测。变更收件人、发件人或附件后重新检查。 |
| 手机离线范围 | 每个账号默认缓存最近 30 天邮件正文，附件按需下载。桌面保留已同步正文，支持按账号打开全量附件下载。主动固定的文件夹优先于普通缓存范围，本地导入件、草稿和固定资料免于常规缓存清理。 |
| 出发前检查文件夹 | 按邮箱和文件夹核对可读正文、已在本机的附件、缺失附件及可估算字节。准备后须能断网从原信打开原件；下载失败、空间不足和大小未知分别说明，可再次准备。压缩节省、附件去重节省和已清理缓存分别核算。 |
| 首批实际接入验证 | 本轮先按 **163 邮箱和 QQ 邮箱** 安排联测。用专用测试账号检查双方收发中文正文与附件、已发送副本、草稿恢复和回复身份。端点连通及本机模拟分别记录，只有服务商授权后的实测才计入兼容性结果。 |
| 固定常用搜索（R06） | 将邮箱范围、关键词及「含附件」或「未读」保存为命名的快捷文件夹。后来加入的匹配邮件可从同一入口查到。进入结果可打开原信。取消固定后，原信及其文件夹归属保持原样。 |
| 等对方回复（R08/R09） | 写信时预设期限，或从已发送原信设置。草稿及仍在发件箱的邮件不启动倒计时。计时以发送时间为起点。在同一邮箱的本地往来中找到原收件人较晚发来的信，且回信引用原信 Message-ID 时，结束提醒并提供回信入口。支持手动关闭。服务商尚未同步时写明查看范围，有最近同步时间时显示来源和时点。 |

### 邮箱兼容性怎么标

| 验证对象 | 首选路径 | 独立记录的验收范围 |
| --- | --- | --- |
| 163/126、QQ、通用 IMAP 邮箱 | IMAP 收取、SMTP 提交；按服务商要求启用协议并授权 | 验证收发、中文文件夹、移动、已发送副本、服务商尺寸限制；公开发布支持列表只填写实际通过的提供方与版本。 |
| Gmail | 系统浏览器 OAuth，经服务商允许的协议直连 | 验证授权、撤销与刷新、标签映射及去重；公开 OAuth 发布审核与测试用户授权分别记录。 |
| Outlook.com、Microsoft 365 | 委派授权；协议能力可用时直连，协议关闭时验证 Graph 路径 | 区分个人账户与组织租户、管理员策略、邮件和日历权限。单个测试租户通过不能推广至所有 Exchange 部署。 |
| 旧式 POP3、企业自建 Exchange | POP3 下载配 SMTP；自建 Exchange 逐部署核实开放协议或接口 | POP 以保留服务器副本为默认，清楚展示文件夹/标志同步限制。自建环境以真实接入方式记兼容性，完整专有协议互通保留为对标缺口直到验证。 |

### 桌面与手机操作

邮箱范围在同一工作区内持续生效。选择一个账号后，收件箱、星标、草稿、发件箱、已发送、归档、附件、邮件搜索和 AI 查信共用这一选择。桌面按账号展开文件夹，手机在同一抽屉内先选账号再选文件夹。选定目标后切换列表并更新数量；取消选择保留原页面。邮件搜索、附件和 AI 查信支持保留原查询切换范围。「全部邮箱」按封显示所属邮箱；重名时用地址区分。从单一邮箱新建邮件默认使用该发件身份，回复默认使用原信所属邮箱。

桌面从账号及文件夹进入列表、再进入正文，支持键盘导航、可调栏宽、独立写信窗口与文件拖入。手机从统一收件箱首屏进入正文，返回保留滚动位置、筛选和选中账号；从系统分享菜单接收文件，支持系统返回、暗色、大字号和屏幕阅读。通知默认提供最少内容，可在本机单独开启预览。发送、清空和移除账号都要让当前作用范围可见。

| 本地压缩 | 固定一份混合样本，在同一设备、相同索引/缓存及去重策略下，对比启用和关闭压缩的两份干净档案。核对含头部与认证标签的对象字节及实际分配空间，单列数据库、索引、预览和临时峰值。固定混合样本在清理临时文件后的完整档案实占须低于原样基线；已压缩格式无净收益时保持原样。全部原件和附件经阅读、导出、备份恢复后 SHA-256 一致；移动端测冷读、大附件首段、峰值内存、耗电及中断恢复。 |
| 容量与速度 | 第一轮建议使用 3 个模拟账号、共 10 万封合成邮件，分别测桌面与首测手机。热索引条件下，中文组合搜索首屏 P95 目标 1 秒内，30 次独立查询；首启建索引耗时、峰值内存、磁盘占用另记。容量压力另用 100 个账号配置验证分页与限并发。上述数值均待实测。 |

## 实施顺序

1. **A · 四端打通。** 先做本地工作区、EML、无损压缩读写、中文索引、系统凭据和测试邮箱往返；把 iOS/Android 后台唤醒及 Windows 离线安装一并验证。跨端封装若在真机上无法可靠隔离正文或恢复草稿，先调整宿主，再铺开界面。
2. **B · 日常替用。** 完成多账号、离线队列、会话、规则、输入与附件、待办、签名等高频功能。在电脑和手机各完成一次从收件、搜索、回复到归档的完整工作流。
3. **C · 会员目标与发布。** 补齐对照项，验证离线模型、大文件外链、局域网同步、服务商能力与失效路径。以实际四端安装、升级、对照项测试和公开差异清单作为发布依据。公开资料中尚未具名的会员权益仍需用版本化权益页或厂商材料补齐。
