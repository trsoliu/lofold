## LoFold 0.2 的迁移和联测

2026-11-21，macOS 开发版接入只读账号导入和单账号样信联测。邮箱大师 4.17.25 的本机账号表可读。导入范围为个人 163、QQ 和 Gmail 的有效地址。Gmail 使用其账号策略允许的应用专用密码。[Gmail 授权说明](https://support.google.com/accounts/answer/185833)

LoFold 的 Rust 客户端在隔离的 GreenMail 中用 TLS 完成授权、SMTP 提交、IMAP 查收，并验证中文 CSV 文件名和 32 字节内容。归档升级、账号去重、提交结果不明时阻止重复发送等测试通过。163 和 QQ 公共端点的证书及主机名也再次验证通过。真实账号的 SMTP 投递及 IMAP 查收需单独授权后验证。

在 QQ 个人邮箱的真实自投中，SMTP 接收后样信抵达收件箱，中文 CSV 名称和 32 字节内容从原件核对通过。QQ 重写了 `Message-ID`，并将 LoFold 原始标识保留为 `X-OQ-MSGID`。0.2.2 支持按该原标识查收。服务器不索引此字段时，只在最近 24 封主题含 LoFold 的候选信中读取邮件头，精确匹配标识后再拉取原件。隔离 TLS 回归覆盖直接查找与邮件头查找两条路径。

启动本机测试服务后，根据服务终端输出填写测试 CA 路径和测试端口，再运行同一个 Rust 协议测试。

```sh
LOFOLD_FIXTURE_CA=/path/to/test-root.pem \
LOFOLD_FIXTURE_SMTPS=43465 LOFOLD_FIXTURE_IMAPS=43993 \
cargo test --locked -p lofold-mail-network -- --include-ignored
```

## 本机复验入口

从项目根目录运行，Python 只使用标准库。直接运行离线列出预设，增加 `--tls` 后连接四个公共端点。此轮四处均通过证书链和主机名校验，协商结果均为 TLS 1.3。检查过程中没有登录服务商账号。[接入检查脚本](../研究/首批邮箱接入检查.py)

```sh
python3 -B 研究/首批邮箱接入检查.py
python3 -B 研究/首批邮箱接入检查.py --tls
```

本次使用的 macOS Python 未配置默认 CA 证书文件，复验时在命令末尾加 `--cafile /etc/ssl/cert.pem` 选用系统信任包。证书验证失败会返回非零退出码。

在获得专用测试账号后，账号持有人可以在本机终端单独验证授权。工具在终端询问地址与授权码，授权码隐藏输入。成功会分别报告 IMAP 只读打开 INBOX、SMTP 认证通过，全程无邮件内容读取或投递。授权码仅存在本次进程内存。

```sh
python3 -B 研究/首批邮箱接入检查.py --verify-account --provider 163
python3 -B 研究/首批邮箱接入检查.py --verify-account --provider qq
```

需要验收实际往返时，账号持有人在本机交互终端执行以下独立模式。输入两只专用测试邮箱后，工具先展示两个投递方向，只有输入「发送两封样信」才继续询问授权码并连接服务商。本轮仅在本机回环与测试替身验证该逻辑，未使用真实账号执行此命令。

```sh
python3 -B 研究/首批邮箱接入检查.py --roundtrip
```

工具首先从 163 向 QQ 提交一封自带 32 字节 CSV 的中文样信。QQ 的 INBOX 在 90 秒内按随机 Message-ID 唯一命中、核对标识、地址、主题与附件字节通过后，才会从 QQ 向 163 提交一封回复，并核对回复身份及会话引用。两侧都以只读模式打开收件箱，使用 BODY.PEEK 读取匹配样信。若 IMAP 不支持按邮件标识搜索、邮件被分流、投递超时、认证失效或连接中断，终端会显示当前错误并结束。每个方向最多提交一次；已显示提交标识时，应先凭它核对收件箱再决定是否重新测试。测试生成的邮件会留在专用账号中。

## 本轮双账号协议实验

复用了原有 GreenMail 2.1.15 固定构件及其校验和，在回环地址分别建立虚构的个人和工作邮箱。个人账号经 SMTP 认证发送中文文件，工作账号用 IMAP 取回并逐字节核对 32 字节的 CSV。工作账号通过自己的 SMTP 身份回复，个人账号收到后核对发件地址、收件地址和原信 Message-ID。两个方向在对应收件箱各收到一封，另一个收件箱均无同一 Message-ID。运行原有故障用例时，丢失最终确认后收件箱已有一封，故意重提后变成两封。[回环收发脚本](../研究/本机收发对照.py) · [已有实验及构件来源](../研究/实验记录.md)

```sh
python3 -B 研究/本机收发对照.py /path/to/greenmail-standalone-2.1.15.jar --java /path/to/java
```

## 真实账号验收条件

1. 分别确认两个专用账号的 IMAP 和 SMTP 授权；授权失效时可针对该账号重新授权。
2. 在客户端用 163 发往专用 QQ 账号，带中文文件名的合成附件；收件方核对一封、字节一致。QQ 原位回复，再核对 163 的收件、两侧发件身份、已发送副本及会话关联。
3. 两侧分别保存带附件的草稿、重启恢复，再提交一次；核对恢复时发件身份和附件字节。验证普通 IMAP 中文文件夹、移动和已读同步，网络中断时展示真实队列状态。
4. 分别记录平台、客户端版本、协议步骤和结果。完成真实投递后才可将对应版本和提供方列为已验证。当前脚本是研发验证工具，运行时的同步与发件队列由选定的单一邮件内核承担。
