# 技术选型与四端安装

状态为提议，日期为 2026-11-20。四端验证样例通过后，由项目维护者确认采用。整机路线同时评估 Meron 和 Allodia 客户端的开源部分。若采用自有宿主，建议 **React + TypeScript + Vite、Tauri 2 和 Rust**，原创代码拟采用 Apache-2.0。所有路线的基础与高级功能均对用户免费。文中的构建命令对应自有 Tauri 宿主。下文是第一阶段的建设与验收方案，安装包、签名、商店审核和实机结果均待实施。

## 一、采用自有宿主时如何选框架

同一封邮件在手机上需要单列阅读，在桌面上需要列表与正文并排。React 复用组件、业务状态和交互约定，布局分别适配。Rust 复用协议、持久化和任务执行逻辑。后台时机、密钥、通知、系统分享和安装交由各端处理。

| 备选路线 | 直接收益 | 主要成本与失败条件 | 调整与回退 |
| --- | --- | --- | --- |
| Electron 桌面 + Capacitor 移动 | 桌面 Node/Chromium 生态成熟，能复用 React 页面和一部分工具 | Electron 自带 Chromium 和 Node，移动端另有宿主。套接字、凭据、签名、休眠恢复需要两套桥接与发布验证。移动端仍要原生实现 | 适合已有 Electron 邮件核心的团队。若 Tauri 桌面 WebView 长期达不到编辑或无障碍要求，可单独换桌面壳，保留邮件核心 |
| **Tauri 2 + React + Rust** | 四端共享界面与核心，Swift/Kotlin 薄插件能直接调用系统能力。与现有 React/TS、分包及 Apple 原生开发经验衔接 | 须维护 Rust、C 库交叉编译与系统 WebView 差异。后台任务能否在没有界面时运行、中文输入法与富文本表现均须真机验证 | 先实现下文验证样例。局部失败先替换对应系统插件或编辑器。若移动壳稳定性持续不足，保留 Rust 公共接口，以原生宿主接入 |
| Flutter + Dart | 官方支持四个目标系统，控件渲染一致，可用平台通道调用原生能力 | 需要迁移 React 组件与编辑器。富文本邮件展示、系统输入与安全存储仍须专项验证。团队长期维护 Dart 和原生接口 | 适合已有 Flutter 邮件团队。只有跨端交互原型与维护投入实测优于当前路线时，才重评 UI 层。可通过 FFI 保留 Rust |

平台覆盖和扩展点可核对各框架说明。[Tauri 分发](https://v2.tauri.app/distribute/) · [Tauri 移动插件](https://v2.tauri.app/develop/plugins/develop-mobile/) · [Electron](https://www.electronjs.org/docs/latest/) · [Capacitor](https://capacitorjs.com/docs) · [Flutter](https://docs.flutter.dev/reference/supported-platforms)

**现有客户端与内核。** Meron 和 Allodia 的开源客户端均进入四端整机评估。自有宿主路线评估嵌入 Allodia 的独立同步引擎，按需移植 Velo 的桌面组件。三条路线的许可、源码、实验及退出条件见[完整方案与选型评审](06-完整方案与选型评审.md)。

## 二、组件、许可与验收重点

| 层 | 建议选型与许可 | 具体职责与进入发布条件 |
| --- | --- | --- |
| 工作区与呈现 | pnpm workspace、React、Vite（MIT），TypeScript（Apache-2.0） | 应用、UI 组件、IPC 契约按包声明依赖，根命令聚合构建。前端只接收界面所需 DTO，邮件凭据与数据库密钥留在原生层。[pnpm](https://pnpm.io/workspaces) · [React](https://github.com/react/react/blob/main/LICENSE) · [Vite](https://github.com/vitejs/vite/blob/main/LICENSE) · [TypeScript](https://github.com/microsoft/TypeScript/blob/main/LICENSE.txt) |
| 客户端宿主 | Tauri 2（MIT 或 Apache-2.0），Swift、Kotlin、Windows API | 平台层做生命周期、系统授权回调、通知和凭据。正文放在关闭脚本、隔离 IPC 的渲染环境，显式配置自定义命令的调用方。验收普通邮件正文无应用命令权限、默认无外链图片或样式请求。[权限模型](https://v2.tauri.app/security/capabilities/) · [Tauri 许可证](https://github.com/tauri-apps/tauri) |
| 协议缺口的备选库 | Cargo workspace、Tokio（MIT）。候选 async-imap（MIT 或 Apache-2.0）、lettre（MIT）、mail-parser（MIT 或 Apache-2.0） | Tokio 管连接与取消。IMAP 按服务端能力增量取件，lettre 组信与 SMTP 投递，mail-parser 解 MIME。用中文编码、混合附件、断线重连、OAuth 和异常响应验证各库。POP、Exchange 等另按适配器验证。SMTP 提交后响应丢失显示“发送结果待确认”，避免盲目重发。[Tokio](https://github.com/tokio-rs/tokio) · [async-imap](https://github.com/chatmail/async-imap) · [lettre](https://github.com/lettre/lettre) · [mail-parser](https://github.com/stalwartlabs/mail-parser) · [SMTP](https://www.rfc-editor.org/info/rfc5321/) |
| 本地数据与搜索 | rusqlite（MIT）、SQLCipher Community Edition（BSD 风格许可）、SQLite FTS5 | 四端编译同一社区版并启用 FTS5，数据库、索引一起加密，外置附件单独加密。中文搜索用 1 字、2 字、完整人名及文件名验收，短词采用单独索引或限定范围匹配。SQLCipher 社区版需按原文保留署名与许可。[rusqlite](https://github.com/rusqlite/rusqlite) · [SQLCipher 社区版](https://www.zetetic.net/sqlcipher/community/) · [FTS5 分词规则](https://www.sqlite.org/fts5.html) |
| 邮件原件和文件的无损压缩 | Zstandard 标准帧 + 原样块；上游 libzstd 提供 BSD 或 GPLv2 双许可。Rust 组件只负责编解码，封装和认证由存储层负责。 | 先以 3 级、独立 256 KiB 块评估压缩率、单封读取的首段时延和手机功耗。Gzip/DEFLATE 可作成熟对照；更高压缩级别只在冷档案实测收益抵得过写入成本时启用。无收益直接原样。安装包负责携带兼容的解码器，运行时离线可用。[Zstandard](https://github.com/meta/zstd) · [BSD 许可](https://github.com/meta/zstd/blob/v1.5.7/LICENSE) · [本机压缩实验](../研究/本地压缩实验.md) |
| 凭据与授权 | iOS/macOS Keychain、Android Keystore、Windows 当前用户 DPAPI | 随机数据库主密钥由系统保护。Android 用 Keystore 密钥封装持久化的密钥和令牌。凭据及邮件缓存从自动云备份排除，本地加密导出通过用户口令跨设备恢复，邮箱凭据重新授权。OAuth 使用系统浏览器、PKCE 及已注册回调。Gmail 的 IMAP/SMTP 邮件权限涉及公开应用验证，Microsoft 还受租户协议策略限制。每种提供商须留一次独立接入实测。[Keychain](https://developer.apple.com/documentation/security/keychain-services) · [Keystore](https://developer.android.com/privacy-and-security/keystore) · [DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) · [原生 OAuth](https://www.rfc-editor.org/rfc/rfc8252.html) · [Google](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol) · [Microsoft](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth/) |
| 可选端侧 AI | llama.cpp（MIT）+ Qwen3-1.7B（模型卡标注 Apache-2.0）候选 | 模型按需导入或单独下载，记录来源、版本、量化参数、哈希和许可。安装模型前可使用邮件主流程。摘要与写作草案均在本机运行，由用户确认写入草稿。验证断网生成、中文质量、峰值内存、取消后释放和低内存设备提示。模型质量、译种覆盖和可运行机型需分别验收。[llama.cpp](https://github.com/ggml-org/llama.cpp) · [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-1.7B) |

自有宿主路线的原创代码建议使用 Apache-2.0。每次发行随包提供源码版本、构建说明、第三方许可与 NOTICE，单列模型和原生依赖。以实际锁文件和分发二进制核对传递依赖。Apple SDK、Windows WebView2 与商店签名分别遵循平台许可。使用独立名称、图标和界面资源实现公开功能。[Apache-2.0 正文](https://www.apache.org/licenses/LICENSE-2.0)

## 三、四端怎么装

下表系统下限是**首轮产品验证目标**。每端至少在建议下限及发布时仍受支持的版本实装一轮。用户可以免费获取客户端。开发者的证书、账号和商店费用由所选分发渠道决定。

| 端与建议首测环境 | 安装路径与构建前提 | 分发、升级和离线条件 |
| --- | --- | --- |
| **Android 10 / API 29+，arm64** | 使用 Android SDK/NDK、JDK、Rust Android 目标构建签名 APK。用户在设备打开 APK，按系统提示允许该来源安装，再启动应用。Google Play 分发另构建 AAB，由商店生成设备所需的 APK | 本地 APK 可离线安装。同包名、兼容签名及递增版本号覆盖升级。商店签名与直装签名要单独规划，避免用户为升级卸载数据。开发者验证按适用地区、设备、渠道复核。[Android 签名](https://developer.android.com/studio/publish/app-signing) · [验证适用范围](https://developer.android.com/developer-verification/guides/faq) · [Tauri Android 构建](https://v2.tauri.app/distribute/google-play/) |
| **iOS 16+，arm64 真机** | 自用时在 Mac 上以 Xcode 选择开发团队和自己的设备，按提示开启开发者模式并安装。免费 Personal Team 的安装描述文件有效期 7 天，到期重新构建并安装。公开测试通过 TestFlight，正式版本由用户在 App Store 免费获取 | App Store/TestFlight 路线需要开发者计划、签名与适用审核，个人计划通常每年 99 美元或当地等值。TestFlight 测试构建有有效期。普通用户通过对应渠道安装和更新。直接交付 IPA 时须核对签名、设备和适用分发资格。已安装后可离线工作。[免费开发账户](https://developer.apple.com/help/account/basics/about-your-developer-account) · [计划费用](https://developer.apple.com/help/account/membership/program-enrollment) · [TestFlight](https://developer.apple.com/testflight/) |
| **macOS 13+，Apple Silicon** | Mac 构建 arm64 应用与 DMG。发布者使用 Developer ID 签名、公证并附票。用户打开 DMG，把应用拖入“应用程序”后启动。自用开发可从本机源码运行 | 已附公证票的 DMG 验证离线首次启动。正式更新使用相同 bundle ID 与受信任签名，新版替换应用并迁移数据。Intel 支持另设 x86_64 构建和真机验收，完成后列入发布说明。[Tauri 分发](https://v2.tauri.app/distribute/) · [Apple 公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) |
| **Windows 11，x64** | 在 Windows 上使用 MSVC、Rust、Tauri 构建 NSIS 安装器。用户运行发行版 `-setup.exe` 后从开始菜单启动。需要集中部署时可增发 WiX 的 MSI，并做独立安装验收 | 提供内嵌 WebView2 离线安装组件的版本，覆盖干净系统无网络的情况。发布版使用可信发布者签名。SmartScreen 还受下载信誉和组织策略影响。覆盖升级沿用相同应用标识、安装范围与数据目录。[离线运行时与安装器](https://v2.tauri.app/distribute/windows-installer/) · [Microsoft 签名与信誉](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation) |

首次启动可直接导入本地 EML。新增邮箱时才与对应服务商完成授权或输入专用授权码。锁屏和退出后，iOS 给后台刷新的时机由系统决定，Android 周期任务最短间隔为 15 分钟且可继续延迟。桌面可在用户准许、进程运行且设备联网时持续收信。恢复前台后立即追平并显示最后同步时间。依赖客户端执行的定时发送，按实际联网及系统唤醒时间记录结果。[Apple 后台调度](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app) · [Android 周期任务](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work) · [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby)

## 四、先做哪些验证，再决定发布

工程建立后，在 Tauri 宿主包目录运行以下构建入口。拟以 `pnpm tauri android build --apk` 生成 Android 直装包，以 `pnpm tauri ios build` 归档 iOS 应用，macOS 与 Windows 各在对应主机运行 `pnpm tauri build`，再执行上表对应的签名及分发步骤。[Tauri 构建命令](https://v2.tauri.app/distribute/)

1. **可重建。** 固定 pnpm、Rust、Node、原生工具版本，提交锁文件。macOS 主机负责 Apple 两端，Windows 原生构建 Windows 包，Android 构建机安装固定 SDK/NDK。每包保留版本、平台/架构、SHA-256、签名身份和构建记录。签名私钥放在发布者控制的凭据库，开源用户可换用自己的签名重新构建。[Tauri 工具链](https://v2.tauri.app/start/prerequisites/)
2. **核心可靠。** 用 Cargo 单元测试和本地测试邮箱验证 OAuth 回调、MIME、断网队列、重连和数据库迁移，另以合成邮件在授权测试账号验证服务商差异。用 Vitest 测 UI 状态，Playwright 测浏览、输入、键盘与窄屏。Windows 宿主采用 WebDriver，Apple 两端用 XCTest/XCUITest，Android 用仪器测试。后台与凭据至少用各端真机检查一次。[Tauri 宿主测试](https://v2.tauri.app/develop/tests/webdriver/)
3. **每端两版安装。** 在干净设备装 A 版，离线读 EML、写草稿，联网收发合成邮件。切后台或休眠，恢复后核对队列。覆盖升级到 B 版，检查账号、附件、草稿、索引及令牌可用性。模拟迁移失败，用升级前的加密快照恢复匹配版本，旧程序禁止直接打开更新后的数据库。
4. **发布结论可追溯。** 每端登记设备、系统、安装渠道、网络、产物哈希和步骤结果。系统阻止安装、OAuth 未审核、设备内存不足或缺实机均按对应条件保留。只把通过安装、升级和真实收发验收的组合列为已支持。
