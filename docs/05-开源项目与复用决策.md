# 开源项目与复用决策

2026-11-20 · 第一阶段补充选型

此文保留各项目的源码入口、协议覆盖与可复用组件。三条路线分别是 Meron 整机、Allodia 客户端的开源部分、Allodia 独立引擎加自有界面。每条路线由一个邮件内核维护业务状态与发送队列。底座选择以[完整方案与选型评审](06-完整方案与选型评审.md)和[本机实验记录](../研究/实验记录.md)为准。

## 三个值得投入时间的项目

| **Meron，四端整机候选** | 同一 Rust 内核，桌面由 Go/Wails 启动，界面是 React/TS；Android 与 iOS 使用 Kotlin Multiplatform，通过 FFI/JNI 接内核。上游已有多账号、文件夹、过滤、离线阅读及各端适配。 | 整机派生须遵守 AGPL-3.0，后续要维护 Go 和 Kotlin。采用这条路线时保留上游的手机端。先验证免账号离线首启、中文邮件、设备后台、迁移与会员功能缺口。[固定版架构](https://github.com/nonbili/meron/blob/v0.5.5/README.md) · [许可证](https://github.com/nonbili/meron/blob/v0.5.5/LICENSE) |

### Meron 能直接省哪些工作

- **安装有真实入口。** 官网给出 macOS 和 Windows 发行包，Android 已有 Google Play 页面。核读中国区 App Store 查询结果，iOS 版 0.5.4 为免费下载，最低版本 iOS 17。桌面固定评估 v0.5.5。原方案中的 iOS 16 是拟定首测目标，派生前须决定是否承担向下适配成本。商店记录只证明分发状态。[四端下载](https://meron.im/) · [中国区 App Store](https://apps.apple.com/cn/app/meron-mail-email-rss/id6782740236) · [Google Play](https://play.google.com/store/apps/details?id=jp.nonbili.meron) · [桌面发布记录](https://github.com/nonbili/meron/releases/tag/v0.5.5)
- **普通收发与数据库有实现。** Rust 清单列有异步 IMAP、SMTP、MIME 构建及带 SQLCipher 的 SQLite。微软邮箱的 OAuth 使用 IMAP/SMTP 邮件权限，使用 Graph 获取资料不能推导出支持 Graph 邮件收发。新品牌公开发行须自行配置服务商授权。[内核依赖](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/Cargo.toml#L10-L34) · [OAuth 端点与权限](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/oauth.rs#L8-L21)
- **备份与隐私要补实。** 已核读的设置备份命令排除了邮件、正文和同步状态，并允许选择是否带出凭据。我们的换机要求是加密携带邮件原件、排除凭据、待发项暂停。上游头像功能还可能访问外部服务。以上两项要在四端以实际导出内容和网络记录验收。[设置备份源码](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/backup.rs#L1-L13) · [隐私说明](https://meron.im/en/privacy) · [开发者商店说明](https://apps.apple.com/us/app/meron-mail-email-rss/id6782740236)

另有两处能直接决定 Meron 的改造量。固定版已有邮件原件归档、哈希和索引重建。桌面另有本地文件夹的加密备份及恢复入口，四端完整换机还要验证其他数据和待发项。移动发送路径直接调用 SMTP，相关函数将传输错误返回调用方；从这条路径尚未证实重启后能区分“确定未发”和“服务商可能已收”。已有规则能给邮件加标签或移动文件夹，针对已发送邮件执行规则与预约投递需要分别验证。[原件归档](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/store/archive.rs#L1-L49) · [移动发信入口](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/protocol/mail.rs#L188-L305) · [SMTP 提交](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/smtp.rs#L720-L748) · [规则执行](https://github.com/nonbili/meron/blob/v0.5.5/meron-core/src/engine/rules.rs#L21-L66)

### 为什么同步优先看 Allodia，桌面交互优先看 Velo

**用同一个失败场景比较。** 如果邮件已经提交给 SMTP，但设备赶在服务商返回最终确认前断线，收件人可能已经收到。Allodia 的 SMTP 实现显式产生“结果不确定”，队列测试还检查了再次运行时不会重复发送。Velo 虽然已有离线操作队列，但固定版定时发送器直接调用 Gmail 客户端，并把瞬时错误重新置为待处理。它的定时界面值得借鉴，普通 IMAP/SMTP 的定时调度与重发语义仍须另验。[Allodia 的 SMTP 确认](https://github.com/allodia-eu/email-calendar-sync-engine/blob/a3cfc21e4d84920980b80f15d73cd04e956a4c1e/crates/provider-imap/src/smtp.rs#L313-L333) · [Allodia 的防重发测试](https://github.com/allodia-eu/email-calendar-sync-engine/blob/a3cfc21e4d84920980b80f15d73cd04e956a4c1e/crates/engine-sync/src/tests/drain/sends.rs#L113-L137) · [Velo 定时发送器](https://github.com/avihaymenahem/velo/blob/4b3efd568a97b8593cff7770908c15dc82045d44/src/services/snooze/scheduledSendManager.ts#L27)

采用 Allodia 时，以它的写入队列作为执行者，界面只显示投递状态。先验证加密数据库、中文一至两字搜索和原始 EML 导出。其默认存储将原件字节另写入磁盘，即便替换数据库驱动也要另外处理外部文件。Velo 的阅读器则在独立样例中验证中文排版、内嵌附件与无外链请求后再接入；主题、地址与正文不进入第三方头像或远程 AI 接口。[Allodia 原件存储](https://github.com/allodia-eu/email-calendar-sync-engine/blob/a3cfc21e4d84920980b80f15d73cd04e956a4c1e/crates/store-sqlite/src/blob.rs#L83-L109) · [Velo 头像获取](https://github.com/avihaymenahem/velo/blob/4b3efd568a97b8593cff7770908c15dc82045d44/src/services/contacts/gravatar.ts#L94)

## 直接使用的配置和测试工具

- **Thunderbird ISPDB 邮箱配置库**已收录 163、126、QQ 等服务商。可以把审核过的 XML 以固定版本随安装包分发，按邮箱域名在本机匹配收发服务器，保留手动配置。这样添加账号时就能预填参数，也无需把用户地址交给第三方查询。数据文件采用 MPL-2.0，协议开启、授权方式与真实收发另行验证。[163 配置](https://github.com/thunderbird/autoconfig/blob/89f9b17749334e32cfaeef605a5ed2b5930b639e/ispdb/163.com.xml) · [QQ 配置](https://github.com/thunderbird/autoconfig/blob/89f9b17749334e32cfaeef605a5ed2b5930b639e/ispdb/qq.com.xml)

- **GreenMail** 可在本机提供 SMTP、IMAP 和 POP3 测试邮箱。四端用同一批合成中文邮件测收发、密送和附件，复用上游服务即可。SMTP 确认丢失另用可控断点模拟；Gmail、微软和国内邮箱的 OAuth 与限流需专门的测试账号。[GreenMail](https://greenmail-mail-test.github.io/greenmail/)
- **Thunderbird / K-9** 适合做行为对照。用同一封中文、多附件或会议邀请邮件对照显示结果，检查手机断网后的文件夹和已读状态。Android 的后端模块可用于定位差异；iOS 与桌面、Android 各有代码与发布路径。[Android 邮件后端](https://github.com/thunderbird/thunderbird-android/tree/2d881297d9005af4d8035d382f078d07aaa0e079/backend) · [iOS 项目](https://github.com/thunderbird/thunderbird-ios/blob/bd4844f2e7f4f15b0c06165e476d96b07a462ef9/README.md)

此前列的 Pimalaya `io-email` 统一封装降为参考。Himalaya 的固定依赖清单表明它实际直接组合较新的 `io-imap`、`io-smtp` 和服务商库。若整机或嵌入引擎缺一个协议能力，只替换那个适配器。核查中在 Mac 上单独提取并运行了 `io-smtp` 的密送头清除和 DATA 正规化纯函数测试，11 项通过；整库 Cargo 测试因依赖下载超时未完成，该结果仅覆盖这些函数。[Himalaya 依赖清单](https://github.com/pimalaya/himalaya/blob/a5623dcac6150f1a8d8ee2d381c4569d7dc815b8/Cargo.toml#L45-L67) · [旧统一封装](https://github.com/pimalaya/io-email/blob/116983e7212b4f8086f44c275c8db697e8c1a189/Cargo.toml#L43-L58) · [SMTP 源码](https://github.com/pimalaya/io-smtp/blob/4d5ed3e39af2a5f27cfbe032928c0317930c3849/src/message.rs)

## 底座怎么定

| 优先验证 | 通过条件 | 对选型的影响 |
| --- | --- | --- |
| ① 四端首次使用 | 不注册产品账号，断网导入带中文附件的 EML，重启后还能搜到、打开、导出；联网时能通过专用测试邮箱往返。 | 能通过的端直接复用。若 iOS 16 是硬要求，把向下适配与替代宿主的实际成本并列评估。 |
| ② 断线和换机 | 删除用户侧已缓存数据前可导出完整原件。模拟提交确认丢失后重启，无自动重复投递；迁移到另一端后不会再发同一封。 | 分别记录两条整机路线的存储、同步与发件队列改动，和独立引擎新建宿主的投入一起比较。 |
| ③ 高价值会员能力 | 同一账号验证规则、快捷文本、多签名、按附件找原信及定时发送。每项标明上游现成、可改造或需要本项目新增。 | 默认外联、本地加密和后台调度单列检查。实际缺口决定工作量，完整会员目标沿用[逐项对照](02-竞品与会员功能对照.md)。 |

这次核查覆盖固定版本源码、上游测试代码、许可证与公开分发信息。尚未构建或实装三个候选的四端版本；网易、QQ、Gmail 和 Microsoft 365 真实邮箱互通也待验证。
